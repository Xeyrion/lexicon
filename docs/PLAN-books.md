## 一、已经有的地基

| 能力 | 位置 | 复用方式 |
| --- | --- | --- |
| 正文清洗、段落切分、分词 | `src/lib/reader.ts` | 直接用于章节文本 |

| 浏览器冒烟 | `scripts/smoke-*.mjs` | 新增书籍路径的用例 |

结论：**UI 几乎不用新写**，工作量集中在解析、目录和长文性能 —— 和 `任务规划.txt` 的判断一致。

## 二、三个需要拍板的选择

### 决策 1：章节是「文章」，还是独立实体？

**方案 A：章节就是 `ReaderArticle`**
- 加可选字段 `bookId` / `chapterIndex`；书本身是轻量索引 `books: [{ id, title, author, chapterIds }]`，放在同一个 reader store
- ✅ 查词、锚点、进度、导出导入**零改动**；阅读列表加一个 `!bookId` 过滤即可
- ❌ 整本书正文都进 `reader.json`，而「调字号」会触发整文件重写 —— 10 MB 的书会让每次点字号都卡一下

**方案 B：新增 `library.json`（第 4 种数据）**
- 书与章节独立存，`reader.json` 保持小而快；阅读进度仍按章节 id 存在 `reader-progress.json`
- ✅ 大书不影响阅读设置写入；「删除整本书」语义清晰
- ❌ 要动 server 的 `KINDS`、缓存键、备份命名、导入导出 payload、设置页列表 —— 约 1–2 小时机械改动，但每处都有现成模式

**我的建议：B。** 书籍模式一上来就是几 MB 正文，塞进 `reader.json` 会让最频繁的写入（字号）变慢；而这个项目已经有成熟的多 kind 机制，现在加比以后迁移便宜。若你想先快速看到效果，A 能省一半时间，之后再迁。

### 决策 2：EPUB 怎么解？

没有现成依赖，需要「解压 + 解析 XML」两步：

- **`fflate`（推荐）**：解压库，约 8 KB gzip；XHTML/OPF/NCX 交给浏览器原生 `DOMParser`
- `jszip`：约 30 KB，API 更友好，功能等价
- **不引入 `epub.js`**：它带整套排版渲染引擎，而我们要的只是「取出纯文本」，用不上

风险：脏 EPUB（缺 OPF、非标准 NCX、编码不规范）不少。解析器必须**每一层都能失败回退**：目录解析失败 → 按 spine 顺序、用文档里的 `<h1>/<h2>` 猜标题 → 再不行就整本一章、交给手动修正。

### 决策 3：章节怎么切？

| 格式 | 主策略 | 兜底 |
| --- | --- | --- |
| EPUB | nav.xhtml / NCX 的 TOC | 每个 spine 文档一章，标题取首个标题标签 |
| Markdown | `#` / `##` 标题 | 整篇一章 |
| TXT | 常见章节正则（`第X章`、`Chapter N`、纯数字标题行） | 整篇一章，手动拆 |

三种都要落到同一个「目录预览」页面，允许改标题、合并、拆分、删章、调顺序。

## 三、里程碑

### 2a 解析与数据（1–2 天）
- `src/lib/epub.ts`：解压 → 读 OPF → 按 spine 取章节 → 读 nav/NCX 拿标题
- `src/lib/bookImport.ts`：TXT / MD 切章，统一输出 `{ title, chapters: [{ title, text }] }`
- 类型 + 校验器 + 单测（用构造出来的最小 EPUB/纯文本，不依赖真实文件）
- 存储：决策 1 选 B 则加第 4 个 kind

### 2b 阅读与导航（2 天）
- 书架入口（`/read` 顶部 tab：文章 / 书籍，或独立 `/books` 冲突需改名）
- 目录抽屉、上一章/下一章、章节进度
- Reader 页面接收章节，复用查词与锚点

### 2c 目录预览与修正（1–2 天）
- 导入后先给预览页：章节列表 + 每章字数 + 合并/拆分/改名/删除
- 解析失败时给「手动指定切分规则」

### 2d 收尾
- 大文件导入的进度与错误提示
- 冒烟脚本加书籍用例；ISSUES / README 更新

## 四、本阶段明确不做

- EPUB 内嵌图片、样式、脚注跳转（只取纯文本）
- 双栏 / 注音 / 分页阅读
- 书签、批注、全文搜索（第三阶段再说）
- 云同步

## 五、风险

1. **脏 EPUB 解析失败率高** → 必须有手动兜底，不能出现「导入后一片空白」
2. **单章过长** → 沿用 `MAX_ARTICLE_CHARS = 20 万字符`，超长章节要在预览页提示并建议拆分
3. **整本体积** → 选 A 时 `reader.json` 会明显变大；选 B 时 `library.json` 也要进备份，注意备份目录占用
4. **进度语义** → 「读完整本书」与「读完本章」要分开显示，别混成一个百分比
